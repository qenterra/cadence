# Support

## Contact routes

- Product support, product help, and technical questions: [support@qenterra.com](mailto:support@qenterra.com).
- Proposals, general enquiries, and commercial matters: [contact@qenterra.com](mailto:contact@qenterra.com).

These mailboxes are not vulnerability or conduct-reporting routes. Follow `SECURITY.md` for vulnerabilities and `CODE_OF_CONDUCT.md` for private conduct reports.

## Usage questions

Read the [documentation](https://github.com/QenTerra/cadence/tree/main/docs) and existing issues first. Use [support@qenterra.com](mailto:support@qenterra.com) for direct product help or technical questions. Use https://github.com/QenTerra/cadence/issues for reproducible public questions that contain no sensitive data.

## Proposals and commercial enquiries

Use [contact@qenterra.com](mailto:contact@qenterra.com) for proposals, general contact, partnerships, and commercial matters.

## Bugs and feature requests

Use the structured issue forms. Include the affected version, environment, exact steps, expected behaviour, actual behaviour, and a minimal synthetic example.

## Security

Follow `SECURITY.md` and use https://github.com/QenTerra/cadence/security/advisories/new. Do not disclose vulnerabilities publicly before coordinated disclosure.

## Scope

Open-source availability does not promise an individual response time, custom implementation, data recovery, or support for unsupported versions. State any paid, contractual, or service-level support separately.
